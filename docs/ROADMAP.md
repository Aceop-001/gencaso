## Unsupported / known gaps
- Hyperliquid API exposes only the 10,000 most recent fills — older P&L is flagged missing (Surf backfills what its warehouse holds, back to a capped window; anything older stays flagged).
- Hyperliquid spot fills, vault deposits and sub-account transfers are excluded/treated as transfers.
- Polymarket requires the proxy wallet address; SPLIT cost allocation is approximate (flagged).
- Solana addresses are recognised but no Solana protocol is integrated.
- In-memory cache/rate limiting/usage are per server instance and reset on restart.

## Technical risks
1. **Tax interpretations** — perps and prediction markets are unsettled in every jurisdiction; modules state assumptions but need adviser review before any claim beyond "estimate".
2. **Payload size** — very active wallets return multi-MB datasets to the browser; move to server-side summarisation + paginated events if needed.
3. **Upstream availability** — Frankfurter returned a transient 522 during testing (retry added); Polymarket domains are blocked by some ISPs' DNS. All providers now retry 429/5xx twice (Retry-After honoured, capped at 8 s).
4. **Year parameters** — FY2026-27 (IN), 2026 (DE) and 2026-27 (AU) parameters are marked unverified in-app.
5. **Moving rules** — Korea (2027 start), Pakistan (proposed crypto CGT), Türkiye (bill status), Vietnam and Indonesia (scope for offshore/derivatives) are provisional and need re-checking as laws change.
6. **OpenSea keys (2026-11-05)** — OpenSea now rejects keyless reads (401 "Missing an API Key") and its free-key service returns 429 to busy IPs, including shared hosts. Free keys are best-effort only (15-minute cooldown after a failed mint, clear error); production needs OPENSEA_API_KEY.
7. **NFT backup (2026-11-05)** — when OpenSea can't be read, NFT trades are rebuilt from Blockscout (Ethereum, Optimism, Base, Arbitrum, Polygon; no key): NFT transfers + the wallet's net ETH/WETH/BETH/stablecoin flow per transaction, ignoring exact pass-through forwards of smart-account wallets. Verified on 0xd6c0…d5e8: 14/14 OpenSea trades matched; sells ≈1% below OpenSea's gross price (the fee actually paid). Base, Arbitrum and Polygon need a browser-like User-Agent (403 without one). One slow transaction (the per-transaction internals endpoint takes 25 s+ on marketplace transactions) no longer loses a whole chain: ETH legs come from one paged wallet-wide read, per-transaction failures are counted and skipped, and a 28 s budget keeps the analysis inside the host's request timeout. HyperEVM (Hyperliquid's EVM) has no keyless explorer API, so those trades still need OpenSea.
8. **NFT backup v3 (2026-11-06)** — no per-transaction requests at all: per chain, four wallet-wide lists (NFT moves, ERC-20 payments, internal ETH legs, the wallet's own transactions), each read only back to the oldest NFT move, then matched locally. Fixes the recurring "transaction(s) could not be read (timed out)" and spam-airdrop wallets exhausting the budget (0x15ba…: 0 trades → 4, stable over 3 runs). Chains run in parallel with per-host pacing; a chain hiccup is retried once without double-counting. Polygon's native coin is priced as POL (was counted as ETH). Liquidity-position NFTs (UNI-V3-POS etc.) are excluded as DeFi deposits. Verified: 0xd6c0…d5e8 16/16 OpenSea trades matched in 11–16 requests.
